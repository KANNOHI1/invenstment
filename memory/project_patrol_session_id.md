**★ 2026-09-18 ユーザー決定: 毎朝の自動巡回は廃止。「随時監督に聞く」運用へ。** 理由: 固定セッションを `--resume` で使い回すと履歴が積み上がり、1ターンの cache read が 9/11 256K → 9/18 612K（8日で 2.4 倍）、1日 7,000 万トークンに達した。CLAUDE.md の「定型処理は独立セッション化」に反していた（固定セッションにしたのはスマホの Remote Control スレッドとセッション内 cron のため）。停止処理: Task Scheduler `InvestmentMorningPatrol` / `Safety` は無効化（削除せず）、巡回セッションの cron は削除確認済み。**再開するなら毎朝新規セッション**（文脈は `rotation_state.md` 冒頭ブロックと `thesis_register.md` にある）。**教訓: 定期実行を固定セッションの `--resume` で回すと必ず肥大する。cron を持ちたいなら Task Scheduler で新規セッションを毎回起動する。** 以下は廃止前の記録（参照用）。


毎朝の巡回（ブリーフィング）を出す**固定セッションの ID は `36358243-ef8c-4c8b-ba08-30112934c274`**。
ターミナルの `claude` ウィンドウで、`scripts/run_patrol.cmd` の `SID=` と同じ値。transcript は
`~/.claude/projects/C--Users-c6341-Documents-Projects-invenstment/36358243-....jsonl`。
Remote Control 経由でスマホの「Morning patrol」スレッドに届く。

**デスクトップアプリ（Code タブ）のセッションは巡回のオーナーになれない。**
理由2つ: (a) セッション ID を持つ claude プロセスがプロセス一覧に現れないため、`run_patrol.cmd` の
ALIVE 判定が常に「窓が死んでいる」と誤認する (b) 外から `--resume` できない（アプリが同じ jsonl を
開いている最中に別プロセスが追記すると壊れる）。よって復旧手段がセッション内 cron だけになり、
PC 再起動で消えたら自力で戻せない。2026-09-10 にデスクトップ側へ移そうとして、翌朝の再起動で
cron が消え、保険が拾った結果**オーナーが2つになり巡回が重複した**。

**ブリーフィングは固定セッション1つがオーナー。** デスクトップ側のセッションは議論・分析・開発に使う。
関連: [[feedback_local_scheduled_claude_pitfalls]] [[feedback_report_via_chat_session]]

**2人体制（2026-09-14 ユーザー決定）。** 「あなたが監督として2人のチーム。必ずあちらのセッションと連携。パトロールは彼の仕事。」
- 連携手段: `ListAgents` に「Morning Patrol」として出る。`SendMessage(to="Morning Patrol")`。返信は `<cross-session-message>` で届く
- 監督のルール: 巡回に影響する変更（スクリプト・登録簿・仕様）は**先に通知してから入れる**。同じファイルを同時に触らない（先方が push するまで待つ）。巡回が見つけた装置の穴・検証したい仮説は監督が受け、菅野さんには監督から持っていく
- 巡回のルール: `rotation_state.md` 冒頭ブロックと `thesis_register.md` を毎回読む。追記は事実と出所のみ

**3セッション体制へ拡張（2026-09-14 ユーザー決定）。** 3人目は**ニュース監視**（毎日 06:35、`holdings.json` の保有を一次でファクトチェックし、確認済／二次のみ／未確認の3段階を付けて `claude_logs/news/YYYY-MM-DD.md` へ書く）。**巡回の材料調査バケツ4「保有銘柄の材料」はこのファイルを読んで代替し、重複検索しない。確認段階は絶対に格上げしない。**
- 受け渡しは `.md.tmp` に書いて `mv` で rename（同一ディレクトリの rename は原子的なので、読み手からは「無い」か「完成品」しか見えない）。完了行を書く約束より構造で防ぐほうが確実
- **rename は「書きかけが見える」しか防げない。「5銘柄のうち3銘柄で力尽きて正常終了」は防げない**ので、読み手（巡回）が保有全銘柄の記載を数える。さらに**日次 ±8% 超が「ニュースなし」で返ってきたら深掘りさせる**（形式は満たしているのに実質が欠ける型。2026-09-15 に SIMO -16.8% が「なし」で返り、実際に踏んだ）

**`ListAgents` の表示名は変わる。セッション ID は変わらない。** 2026-09-16 に監督が `invenstment-12` → `投資（監督）[d6be8b]`、巡回が `Morning Patrol [d3397a]` へ改名され、巡回からは「監督セッションが落ちた」ように見えた。**連絡不能になったら、まず `ListAgents` で名前を引き直す。** `SendMessage` の宛先は名前なので、ID を知っていても直接は送れない。

**VS Code の統合ターミナルは巡回のオーナーになれる（2026-09-16 ユーザー要望で移設・動作確認済み）。** デスクトップアプリと違い、`claude --resume <SID> --dangerously-skip-permissions` を打つと通常の `claude.exe` プロセスが立ち、コマンドラインに SID が乗る。`run_patrol.cmd` の ALIVE 判定はそれを見るので 07:00 のタスクは正しくスキップし、cron・名前・会話は `--resume` で引き継がれる。**同じ SID を2プロセスで開かない**（cron が二重に走る）——移す前に既存窓を `taskkill /T` で落とす。VS Code を閉じると巡回セッションも落ちるが、翌 07:00 のタスクが別窓で `--resume` して巡回自体は出る（窓の場所が戻るだけ）。

**セッションはターミナルのホストを変えても維持される。** 2026-09-16 夜、監督が巡回の窓（コンソール）を閉じ、VS Code の統合ターミナルで `--resume` し直した。**会話履歴・セッション内 cron ジョブ・`ListAgents` の表示名はすべてセッション ID に紐づいており、そのまま引き継がれた**（変わったのは `ListAgents` の ref だけ: `d3397a` → `dbe354`）。窓を移す・落ちた窓を立て直すのは安全な操作で、必要なのは同じ SID で `--resume` することだけ。

**ただしセッション内 cron は「セッション限り・7日で自動失効」。** プロセスが動いていない時間帯は発火せず、7 日経つと最後の1回を撃って消える。**巡回のたびに `CronList` で存在を確認し、無ければ同じ文面で張り直す**（cron ジョブの prompt 自身にこの自己更新を書いておく）。窓を閉じている間に発火時刻を跨いだ場合は Task Scheduler 側の保険が拾う。
