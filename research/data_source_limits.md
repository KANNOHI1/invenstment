# データ取得の制約（2026-08-28 調査）

**結論: クラウド環境からは企業の一次データ（SEC提出書類）を機械で取得できない。** 5回試して回避不能と判断。

## 試したことと結果

| 経路 | 結果 |
|---|---|
| コンテナから sec.gov | **接続不可**（応答コード000。egress遮断） |
| コンテナから金融サイト全般 | **接続不可**（同上） |
| GitHub Actions から www.sec.gov | **403**（SECはクラウド事業者のIPを遮断） |
| GitHub Actions から data.sec.gov | **403**（同上） |
| GitHub Actions から Yahoo quoteSummary（財務） | **401**（認証が必要） |
| GitHub Actions から Yahoo chart（株価） | **成功**（唯一動いている経路） |

## 何が起きていたか

「一次資料で確認した」と報告していたものは、**実際は全て記事の二次引用**だった。記事が引用する数字は出所と時点がばらつくため、以下の事故が起きた。

- IRENの発行済株式数を**37M株誤り**（357M → 実際394,058,648株）
- IRENの希薄化率を**年率14%と誤り**（実際45.7%）— しかも「希薄化の減速が3倍数学の生死を決める」と自分で書いた直後だった
- Q4売上のコンセンサスが$132Mか$157.1Mか、記事によって食い違い決着しない

## 運用上の帰結

- **株価・セクター・金利など、Yahooのchartエンドポイントで取れるものは自動化できる**（現状の相場観レポートはこの範囲で成立している）
- **企業の財務・株数・提出書類は自動化できない。** 判断に効く数字は、人がSECのページを開いて確認するしかない
- **ローカル環境（家庭用IP）ならSECは遮断対象ではない**ため、この制約は消える。企業研究をやるならローカルが適切
