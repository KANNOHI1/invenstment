# 定型レポート「相場観」仕様 v1.0

2026-08-22 制定。`report_template_banmen.md` v0.3（執行準備が中心）を置き換える。

## 何が変わったか

**執行の機械を降ろした。** 売買はユーザーが決定し、変更があれば連絡が来る。こちらの仕事は
**「今どこにいて、資金がどの層にあり、主役は誰か」を毎回積み上げて示すこと**。
買い推奨・株数・指値は書かない。

v0.3の致命的な欠落を埋める: 2026-08-18〜20に金利上昇と原油高で保有が約4%溶けたとき、
機械チェックは3日間「反証なし」と言い続けた。仮説登録簿は「テーマが死んだか」しか見ておらず、
**「サイクルの時計がどこを指しているか」を見る層が一つも無かった。**

## モード

| モード | 起動 | 中身 |
|---|---|---|
| 日次 | 定期巡回 | 座標の**差分**。読み切り1分。変化なしなら「座標に変化なし」＋序列1行 |
| 土曜 | 週末の巡回 | 全層＋**主役層の注目銘柄1〜2本を本格分析** |
| 月初 | 月初の巡回 | 候補宇宙のゼロベース再構築＋総資産の対目標距離 |

## 生成手順

1. `date -u +%Y-%m-%dT%H:%M:%SZ > watchlist/.price-refresh-trigger` → commit・push → 約40秒後 `git pull`。
   **`scripts/fetch_prices.mjs`をローカルで実行しない**（egress遮断で全銘柄403）。
2. **`node scripts/rotation_check.mjs`** — 象限・セクター序列・主役のズレ。
3. **`node scripts/patrol_check.mjs`** — 保有の軌跡と仮説の反証チェック。
4. 材料調査（下記の定型プロンプト）。
5. `watchlist/rotation_state.md` を更新してコミット。

## 5層構成

- **①マクロ座標** — 金利（10年/30年）・原油・ドル・クレジット選好・VIX。数値と20日変化。
  **行動を変えうるものだけ。指数の日次解説は書かない。**
- **②ローテの現在地** — 4象限（金融相場／業績相場／逆金融相場／逆業績相場）のどこか。
  **前回からの移動を必ず書く。** 移動したら「象限移動」と宣言する。
  教科書の処方を書き、それを採らない理由があるならそれも書く。
- **③資金の所在** — 11セクターの相対強度。どこから抜けてどこへ入ったか。
  **教科書の主役 vs 実際に走っている層のズレが最大の情報。** 分裂・不一致なら理由を考える。
- **④主役とその中身** — 今の主役層、その中で実際に走っている銘柄。
  **主役が交代したら「主役交代」と宣言する。** 土曜は注目銘柄を本格分析。
- **⑤保有への言及** — 保有銘柄が座標上のどこにいるか。順風か逆風か、主役層か周辺か。
  **売買推奨は書かない。** 保有は`holdings.json`が唯一のソースで、
  **ユーザーからの連絡があったときだけ更新する。**

## 材料調査の定型プロンプト（Sonnetへ委譲・毎回書き直さない）

**市場の日次解説は取らない。** 4バケツ:

1. **象限を動かす материал** — 金融政策（FOMC・要人発言）、インフレ・雇用の指標、金利と原油の水準変化の理由
2. **セクターの資金移動の理由** — 大きく動いたセクターについて、何が起きたか
3. **主役層の銘柄の材料** — 大型契約・資金調達・格上げ格下げ・決算日程
4. **保有銘柄の材料** — 同上（言及のためであって売買判断のためではない）

指示に必ず含める:「**株価・騰落率・時価総額の数字は報告しない**（別経路で取得済み）」
「生データ・HTML・記事全文を返さない」「日付と出所を添える」「確認できないものは未確認と明記」
「該当なしの項目は1行」。

## 文体ルール

- 方向を語る主張には**日付つき2点**を添える。
- 株価は`latest_prices.json`／`rotation_prices.json`由来のみ。Web検索の株価は使わない。
- 表は最大3列。横長テーブル禁止。
- 日次は読み切り1分以内。

## 仮説登録簿の位置づけ

`watchlist/thesis_register.md`は残す。ただし**発火時の行動は「執行」ではなく「座標の書き換え」**。
例: 仮説Cが崩壊 → 象限判定を見直し、主役を再判定する。売買はしない。
