# 定型レポート「盤面」仕様 v0.3

2026-08-21改訂。v0.2からの変更点は末尾の「改訂理由」を参照。

## 2つのモード

| モード | 起動 | 中身 |
|---|---|---|
| フル版 | ユーザーが「盤面」と発話 | 株価取り直し＋調査エージェント＋全6層 |
| 差分版 | 定期巡回（自動） | 冒頭に「前回から変わったこと」。**該当なしなら2行で終える** |

## 生成手順

1. `date -u +%Y-%m-%dT%H:%M:%SZ > watchlist/.price-refresh-trigger` → commit → push → 約30〜45秒後に `git pull`。
   **`scripts/fetch_prices.mjs`をローカルで実行しない**（egress遮断で全銘柄403になり、良好なスナップショットを潰す。2026-08-21に実際に発生）。
2. **`node scripts/patrol_check.mjs`** を実行する。反証条件・監視線までの距離・保有の軌跡が一度に出る。
   **`node -e`で計算式を手打ちしない**（登録条件が代理指標にすり替わる。2026-08-21の事故記録を参照）。
3. 材料調査（下記の定型プロンプト）。
4. レポート生成後、`watchlist/banmen_state.md` を更新してコミット。

## 6層構成

- **①マクロ**: 金利・原油・地政学・為替。**行動を変えうるものだけ。** 指数の日次解説は書かない。
- **②側とターン**: 今どの側にターンが来ているか。ターンの持ち主が変わったら「ターンチェンジ」として宣言する。
- **③テーマと仮説**: `patrol_check.mjs`の出力をそのまま。反証該当なしなら距離の3行だけ。
- **④保有（軌跡で書く）**: 点ではなく線。含み損益率は**月初のみ**。

  ```
  POWL 15株 $207.01（8/13取得）→ $197.40（日次-0.4%）
  ```

- **⑤アクション（3分割固定）**: 今やること（なければ「なし」と明言）／期限つきの待ち／次の判断日
- **⑥執行準備（毎回必ず書く。攻めの装置）**:
  > **「今この瞬間に執行上限$4,250があったら、何を・何株・いくらの指値で買うか」**

  - 出すのは注文ではなく**執行準備**。ゲート日には「置くだけ」の状態にしておく。
  - **候補の宇宙を保有銘柄に限定しない。** 「銘柄数を増やさない」はポートフォリオの本数の制約であって、探索範囲の制約ではない。**保有リストを投資宇宙にすると、盤面は次の爆益を探す装置ではなく保有の子守り装置になる。**
  - 保有外を見るには `node scripts/scan_rank.mjs`（候補宇宙は`watchlist/.scan-tickers`で管理、月1でゼロベース再構築）。
  - **保有外が勝ったら、追加ではなく入れ替えを設計する**（弱い1本を降ろして乗り換える）。本数は増やさない。
  - 買わない結論も可。その場合は**「何が起きたら買うか」を必ず書く**。

## 材料調査の定型プロンプト（毎回書き直さない）

Sonnetのサブエージェントへ。**4バケツだけ**を調べさせる。**市場の日次解説は取らない。**

1. 保有銘柄の企業アクション（大型契約・資金調達／希薄化・格上げ格下げ・決算日程変更・訴訟）
2. **仮説Dのkillスイッチ関連**（ハイパースケーラーのcapexガイダンス修正、NVIDIAの需要トーン、メモリ契約価格の前四半期比）
3. 期限つきイベントの結果（その時点で待っているもの）
4. 盤面の前提を壊す材料

指示に必ず含める: 「**株価・騰落率・時価総額の数字は報告しないこと**（別経路で取得済み）」「生データ・HTML・記事全文を返さない」「日付と出所を添える」「確認できないものは未確認と明記」「該当なしの項目は1行で終える」。

## 文体ルール

- 方向を語る主張には**日付つき2点**を添える。
- 株価は`latest_prices.json`由来のみ。Web検索の株価は使わない。
- 表は最大3列。横長テーブル禁止。
- 差分版は読み切り1分以内。該当なしなら2行。

## 定期の見直し

- **土曜（＝米国金曜セッションを見た回）**: 仮説Aの週次判定（`patrol_check.mjs`が自動で出す）。監視条件自体が今のレジームに合っているかを点検する。
- **月初**: `watchlist/.scan-tickers`をゼロベースで再構築。あわせて**総資産の対目標距離**（3倍まで何が必要か）を1回だけ出す。

## 改訂理由（v0.2 → v0.3）

7日連続で「反証ヒットなし → 動かない」を出し続けたことで露呈した欠陥への対処。
- **守りの装置しかなかった**（反証条件は仮説が壊れたかしか見ない）→ ⑥執行準備を新設。
- **視野が保有5銘柄に閉じていた**（保有外の再スキャンを一度もしていなかった）→ 候補宇宙を明示的に外に開いた。
- **機械チェックが手打ちで、登録条件が代理指標にすり替わっていた** → スクリプト化。
- **材料調査が読み物化していた** → 4バケツに限定。
- **保有を点で書いていた**（自ルール違反）→ 軌跡形式へ。
